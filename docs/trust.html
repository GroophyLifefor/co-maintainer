Check it in the code.

co-maintainer is open source and runs on your own server. This page describes where data goes and what is still missing. The code is the final word: everything here can be checked in the repository.

Last updated 2026-11-24 · To hear when this page changes, subscribe to the newsletter.

Where data goes

  • Your server. co-maintainer runs where you install it. It clones the repositories it reviews, and keeps reviews, guides, logs and its database (app.db) on that machine.
  • Your AI provider. To build guides and write reviews, co-maintainer sends repository content to the provider you connect, with your key. This can include the diff, files from the clone, pull request history, comments, issues and the generated guides. That traffic goes from your server to your provider directly. It does not pass through us.
  • MCP servers you add. If you register MCP servers for a repository, a review can call them, so data can reach them too. Pull requests from forks get no MCP tools unless you turn that on.
  • GitHub. co-maintainer reads and writes GitHub through the GitHub App you create, with the permissions listed in the GitHub App docs.
  • Us. The self-hosted version sends no telemetry, usage signal or crash report to us.
  • Version checks. "Check for new versions" in the dashboard reads the public release and changelog from github.com when an admin clicks it. If you set CM_UPDATE_URL, the server reads the latest stable release from GitHub at most once a day, and the version numbers go to the address you set only when an admin presses Update. Requests include the co-maintainer version in the user agent. Diagrams use a PlantUML server only if you turn them on, and that can be your own.

On your server

  • Keys and secrets are stored in config.json in plain text, with file mode 0600. Protect the server and its backups like any secret store.
  • The dashboard password is stored as a scrypt hash. Repeated failed sign-ins lock the address out.
  • The audit log records password and GitHub sign-ins, settings changes, token changes, repository and review actions, dismissals and updates.
  • One dashboard owner per installation, signing in with a password or with one allowed GitHub account. Users, teams and roles are designed and planned.

Known gaps

  • Only known secret shapes are masked. Since 0.7.24, API keys, tokens, private keys, passwords in URLs and JWT signatures are masked before content reaches your provider (see the privacy page for the list). A secret in another shape is sent with the rest.
  • No built-in data export beyond the usage CSV, and no erasure tool yet. Today you remove data by deleting app.db, the config folder and the cloned repositories. This does not remove what your AI provider or GitHub already hold.
  • No SOC 2 or similar certification.

Cloud

Cloud at cloud.co-maintainer.com runs the same software for you on our server, with your own model key. Cloud may be shut down one day. If that happens, we intend to tell users well before. A separate page will describe Cloud data handling.

Reporting a vulnerability

Use private vulnerability reporting on GitHub or email cos@co-maintainer.com. Our target is to confirm a report within 2 business days. The full policy is in SECURITY.md.

Status

The parts we run are checked from a separate server: status page.

Responsibility

A review points at possible problems. The person who writes and merges the code stays responsible for it.
